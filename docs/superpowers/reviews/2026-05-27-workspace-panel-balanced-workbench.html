Balanced Workbench / 重做版评审稿

Workspace Panels 不是没调，而是还没真正重做。

你会感觉“和优化前没什么太大变化”，核心原因不是颜色或圆角没改够，而是 `Explorer / Search / Git` 仍然在用三套不同的 panel grammar。上轮更像修边，不像重建系统，所以视觉感受不可能拉开。

这版评审稿把桌面端和移动端一起收敛到同一套 `section / header / count / actions / row / selected` 语法里。方向不是简单把 Explorer 抄成现在的 Git，而是以 Git 现有结构为骨架，再把三块面板一起压到同一个更紧、更硬朗的 workbench 系统里。

这是一份离线设计稿，不是实现代码。重点是先把“问题在哪、一起改之后长什么样、为什么这样改”讲清楚，再决定是否进入 spec 和落地阶段。

统一对象

Explorer / Search / Git / Mobile
不只统一颜色和圆角，统一的是信息容器、折叠头、行态、密度、触控继承规则。

核心变化

Section Shell First
每一块内容都回到统一 section grammar，标题、计数、动作和 body 一起成系统，但不再用一块一块的外框切割。

设计基调

紧凑 / 硬朗 / 高扫描效率
不走消费型大卡片，也不走软糯圆角；接近专业编辑器 workbench，而不是工具拼盘。

现状截图

这里先把当前桌面端和移动端的真实界面放一起。问题不是某一个面板丑，而是三者像三个产品：结构语言不同，折叠逻辑不同，块感不同。

Desktop

Explorer 当前

`Open Editors` 和 `Workspace` 不是同一种 section 语法；动作散在标题右侧，树内容像单独的控件区。

Search 当前

更像一个塞进 sidebar 的搜索工具页。输入、提示文案和结果容器没有和 Explorer / Git 共用同一层级。

Git 当前

结构最接近目标，但 commit 区依旧偏表单，下面的 section header 和其他面板也没有真正共用一套语法。

Mobile

Mobile Explorer 当前

已经比桌面更完整，但 `Quick Jump / Open Editors / Workspace` 还是三种气质，section grammar 不够统一。

Mobile Search 当前

继承了容器，但没有继承完整 section 系统。它能用，但不像和 Explorer / Git 一家出的。

Mobile Git 当前

能力齐全，但视觉节奏偏碎。commit、section、row 的层次还没回到同一套 compact workbench grammar。

当前问题

这些问题叠在一起，就是“看着没大变化”的原因。因为你感知到的是系统层面的不一致，而不是单点样式。

01

Same Workbench, Three Grammars

Explorer 像树控件，Search 像工具页，Git 像表单加列表。用户在同一个侧栏里切 tab，却要重新学习每块面板的结构语气。

02

Collapse Semantics Are Inconsistent

有的地方 header 是一条文字加 action，有的地方是完整 section 头，有的地方只是结果组名。折叠和收起的 affordance 没对齐。

03

Container Hierarchy Is Fighting The Content

现在很多精力都花在“包住内容的壳”上，导致文件树、结果列表、变更列表本身反而不够利落。面板像块状拼起来，不像连续工具面。

04

Mobile Copies Surfaces, Not Grammar

移动端继承了视觉表层，但没有完整继承 section grammar。结果是它看起来比较整齐，却没有形成和桌面一致的系统感。

统一 Grammar 规则

这次不是“给三块面板各修一下”，而是先定义一套 workbench grammar，再让 Explorer / Search / Git / Mobile 都落到这套 grammar 里。

Header Contract

每个 section 都固定拥有 `chevron / title / count / actions / body`。统一的是 header grammar，不是再额外包一层小卡片。

Control Contract

Search 输入、Quick Jump、Git commit 输入都归入同一档 compact control family，只允许尺寸差异，不允许语气差异。

Row Contract

文件树行、搜索匹配行、Git 变更行、历史行共享同一 selected / hover / focus 规则。密度统一，交互心智统一。

Mobile Contract

移动端只放大热区和间距，不重新发明圆角和容器语言。也就是说，手机上看到的是同一系统的触控版，而不是另一套 App。

为什么不是直接抄现在的 Git

因为 Git 只是最接近 section 化，不代表已经对。它的 commit 区还偏重，信息层级还偏碎。所以方向是“以 Git 的 section 思维为骨架，再把 Git 自己也收紧”。

为什么 Search 也要一起重做

Search 问题看起来小，是因为内容更少。但它恰好最容易暴露 grammar 不一致。只修 Explorer / Git，不修 Search，整个侧栏仍然会像三套产品。

为什么这次感知变化会更大

因为用户首先感知的是 section、row 和密度节奏。这些一旦统一，即使功能没变，整个侧栏也会明显像“同一个工作台”，而不是“局部换皮”。

实现时的控制点

真正要落地时，优先做共享 section / row / control primitive，再去套 Explorer、Search、Git 和 mobile。否则会再次变成各修各的。

如果三块一起改，方向就是这个

这不是单独修 Explorer，也不是让 Git 做唯一模板，而是建立一个真正可复用的 panel system。

1. Explorer 成为基础语法

`Open Editors / Workspace` 都收敛到统一 section grammar，文件树 row 作为所有列表行的基线。

2. Search 回归同一家

输入、过滤、结果组、匹配行全部对齐统一 grammar，不再像塞进 sidebar 的独立工具页。

3. Git 只保留能力，不保留碎感

commit 区缩短，changes / history / worktrees 全部落回共享 section 与 row 语言。

4. Mobile 继承 grammar，不继承混乱

触控尺寸放大，但继续用同一套 section、control、row、selected contract。
